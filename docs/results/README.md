# Result artifact policy

`docs/results` stores compact, reviewable evidence for Vulkax experiments. It is not the long-term store for complete frame sequences or other reproducible binary output.

## Keep in Git

- manifests that record the preset, equation, resolution, frame count, timing and other reproduction metadata;
- JSON/CSV summaries and benchmark measurements;
- small golden/reference assets required by automated tests;
- a deliberately curated still or comparison image when it materially helps the documentation;
- scripts and commands needed to regenerate the result.

## Do not keep in Git

- complete `frame_*.png` render sequences;
- temporary OpenEXR captures that are regenerated by CTest or CI;
- build directories, generated shaders, transient benchmark output or duplicate exports.

Complete render sequences should be attached to a GitHub Actions run or a release when they need to be retained. This keeps clones and diffs small while preserving reproducibility.

## Physics Studio sequence example

The checked `my_wave_sequence/sequence_manifest.json` is the durable record for the previously committed 120-frame wave export. Regenerate the frames locally after building Physics Studio:

```bash
"build-vulkax/Vulkax Physics Studio.app/Contents/MacOS/Vulkax Physics Studio" \
  --export-sequence docs/results/my_wave_sequence --frames 120
```

The generated `frame_*.png` files are intentionally ignored. If a sequence is needed as review evidence, upload the directory as a CI artifact rather than committing every frame.
