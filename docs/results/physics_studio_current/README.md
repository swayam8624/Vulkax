## Checked timeline export

`sequence_wave_field/` contains a 24-frame, 30 fps, 640x360 PNG export generated by the native
Physics Studio application. `sequence_manifest.json` records the equation, preset, frame range,
resolution, timing, and every frame filename. The first frame was visually inspected as a smooth
banded scalar wave field. This is an image-sequence export, not an EXR/HDR or GPU-simulation claim.

## Checked OpenEXR Preview Export

The macOS Physics Studio bundle can export a preview frame as a half-float RGBA OpenEXR file. It
converts the displayed sRGB preview to linear values before writing. The `physics_studio_exr` CTest
path runs the native bundle and `test_openexr_export.py` verifies the OpenEXR magic, channel, and
compression headers. This is a linearized preview export, not a full HDR radiance buffer or an
accumulated offline render.

## Checked Quality-Controller Benchmark

\`quality_controller/quality_frames.csv\` is raw per-frame output from fixed and adaptive
quantum-wavepacket preview policies. Each row records actual CPU analytical sampling time, an
exact-grid resampling MSE, selected resolution scale, selected sample count, and EWMAs.
\`quality_summary.json\` aggregates p50/p95 timing and mean MSE. On the checked 120-frame Apple M2
Pro run with a 1 ms target, fixed preview measured \`9.55 ms\` p50 and zero resampling MSE; adaptive
preview measured \`1.19 ms\` p50, \`0.00162\` mean MSE, and 13 control changes. It is a reproducible
CPU analytical workload, not a GPU or perceptual image-quality evaluation.

For analytical presets, the native editor now displays and uses a fixed-grid sampling MSE alongside
preview frame time and quality scale. Dynamic PDE, particle, and lensing previews deliberately do
not reuse that scalar-field reference; their displayed zero represents an unavailable independent
image reference rather than measured agreement.

## Dynamic Parameter Reproducibility

Reaction-diffusion exposes diffusion, feed, and kill controls, while the N-body preset exposes
central mass, orbiter mass, and softening. A dynamic parameter edit rebuilds deterministic state at
the current timeline time. The checked dynamic-project smoke path saves a modified reaction setup
at 0.5 seconds, mutates it, and verifies that reopening restores the intended parameters and time.

## Checked Schwarzschild Reference

`relativity/schwarzschild_rays.csv` stores equatorial null-ray RK4 runs in geometric units
(`G=c=1`). The weak-field `b=100M` ray measured `0.0412225` radians of deflection against the
leading-order `4M/b = 0.04` radians. The `b=5M` ray is reported as captured because it lies below
the `sqrt(27) M` photon-sphere impact threshold. These are a narrow Schwarzschild reference, not
Kerr, ray-bundle, or film-rendering results.

## Checked Schwarzschild Lensing Preview

`sequence_schwarzschild_thin_disk/` contains a 90-frame native-editor PNG export of the `schwarzschild-lensing`
preset. Captured rays are black; escaped rays use the RK4 equatorial deflection lookup to map an
inclined emissive annulus, with a documented Doppler-brightness heuristic. The Schwarzschild
thin-disk suite verifies the central shadow, bend ordering, and nonempty luminous disk. This remains
a thin-disk Schwarzschild visualization, not a Kerr, ray-bundle, or production-film
claim. The `schwarzschild_lensing` unit test validates capture, weak-field agreement, and monotonic
strong-to-weak deflection before the preview is accepted.

## Checked Buoyant Smoke Example

The buoyant-smoke suite runs a deterministic two-dimensional incompressible stable-fluid solver:
semi-Lagrangian advection, Jacobi pressure projection, temperature/density buoyancy, and vorticity
confinement. Its test verifies finite replay, bounded divergence, source mass, and upward plume
transport. `sequence_buoyant_smoke/` contains a 90-frame native-editor PNG export; the sequence
validator confirms that it contains nonempty changing frames. It is not a 3D volume renderer.

## Persistent Editor GPU Preview

The native physics_studio_gpu_preview_smoke CTest path launches the packaged Physics Studio,
selects Wave Field, and requires a nonempty preview whose backend identifies persistent Vulkan
compute. The editor retains one compute-only Vulkan device, pipeline, descriptor set, buffers,
command buffer, fence, and timestamp query pool for its session. Each Wave Field preview updates
the uniform buffer, dispatches, records a timestamp when Vulkan 1.2 query reset is available, then
reads the scalar field into the Qt image provider. This verifies a real editor-side GPU path; it
does not claim zero-copy sharing with Qt Quick RHI or persistent GPU ownership for dynamic graphs.

The physics_studio_gpu_reaction_preview_smoke CTest path selects Gray-Scott, modifies its feed
parameter, seeks to 0.5 seconds, and requires a persistent Vulkan backend and live GPU/CPU solver
MSE below 1e-10. Gray-Scott retains two GPU field pairs for ping-pong stepping; changing a
parameter or timeline time reconstructs those fields from the deterministic CPU seed. The CPU
graph advances only to measure numerical agreement, while the GPU secondary field is displayed.

`gpu_wave/gpu_wave_agreement.json` records a headless Vulkan storage-buffer compute dispatch of the
wave field and CPU readback comparison on the Apple M2 Pro. At 64x36 samples it measured
`MSE = 1.90944e-13` and `max_error = 8.69864e-07`, below the `1e-5` test tolerance. This confirms
the first real GPU execution path for the wave field. It does not yet establish timing results,
the general AST-generated GLSL path, or GPU agreement for the dynamic simulation graphs.

`gpu_wave_generated/gpu_wave_agreement.json` is the same GPU agreement run using SPIR-V generated
from the canonical `wave-field` AST through `vulkax-equation-shader`, then compiled by
`glslangValidator`. It reports the same `MSE = 1.90944e-13` and `max_error = 8.69864e-07` at 64x36.
This is the checked scalar equation-to-GPU path; other presets still require individual binding and
agreement coverage before they can make the same claim.

## Checked Vulkan Dynamic Simulations

`gpu_wave_simulation/gpu_wave_simulation_agreement.json` records the 64x64 ping-pong Vulkan wave
solver against the deterministic `SimulationGraph` reference for 32 steps. On the Apple M2 Pro,
the checked run reported `MSE = 0` and `max_error = 0`. The wave solver has explicit zero-boundary
behavior and uses the same timestep and spatial coefficient as the CPU reference.

`gpu_reaction_diffusion/gpu_reaction_diffusion_agreement.json` records a two-field, 64x64
Gray-Scott Vulkan ping-pong solver compared against the deterministic CPU reference for 64 steps.
On the Apple M2 Pro it measured `MSE(A) = 7.04e-16`, `MSE(B) = 5.51e-18`, and `max_error =
1.19e-07`, below the `1e-5` agreement tolerance. The same 64-step run recorded `6.73471 ms` of
Vulkan compute timestamp time; it excludes CPU submission, fences, and readback. It preserves the
CPU solver's fixed boundaries, update constants, and clamp. This is a compute-readback correctness
result, not a claim that the interactive editor preview is already GPU-backed.

## Checked N-Body Export

`sequence_nbody_orbits/` contains a 24-frame, 30 fps, 640x360 PNG export of the native editor's
softened Newtonian N-body preset. The CPU reference uses velocity Verlet, starts in a zero-total-
momentum center-of-mass frame, and records deterministic positions from its seed. The sequence
validator checks both PNG consistency and that dynamic frames differ. The companion unit test runs
4,800 reference steps and bounds relative energy drift below two percent. This is a CPU reference
and visualization path; GPU particle integration and instanced particle drawing remain separate
runtime work.

## Checked Vulkan Particle Gravity

`gpu_particle_gravity/gpu_particle_gravity_agreement.json` records a seven-body, two-pass Vulkan
velocity-Verlet implementation. Each integration step performs kick-drift into an intermediate
buffer, inserts a compute read/write barrier, then performs the second kick into the next buffer.
After 128 steps on the Apple M2 Pro, comparison against the double-precision CPU reference measured
`MSE = 1.86e-12`, `max_error = 5.45e-06`, and `15.1534 ms` of summed Vulkan compute timestamp
time. It is an explicit CPU/GPU solver agreement result; the editor's particle viewport remains a
CPU raster preview until persistent GPU field ownership and instanced rendering are integrated.
